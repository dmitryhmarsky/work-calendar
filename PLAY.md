# Публикация в Google Play и монетизация

Пакет приложения: `com.dmitryhmarsky.workcalendar`. Его нельзя изменить после первой публикации. Если хотите другое имя, поменяйте `applicationId` и `namespace` в `android/app/build.gradle` до шага 4.

Что уже готово в репозитории:

- Сборка целится в Android 16 (API 36). Это обязательное условие для новых приложений в Play с 31 августа 2026 года ([требования](https://developer.android.com/google/play/requirements/target-sdk)).
- Workflow **Release AAB (Google Play)** собирает подписанный `.aab` и при желании сам загружает его в Play.
- Политика конфиденциальности: `www/privacy.html` (адрес появится после шага 0).
- Тексты, скриншоты, значок и графика для карточки: папка `store-assets/`.

## Шаг 0. Включить GitHub Pages (один раз, 1 минута)

Нужно для ссылки на политику конфиденциальности.

1. Репозиторий на GitHub, **Settings → Pages**, в поле **Source** выберите **GitHub Actions**.
2. **Actions → Deploy web app → Run workflow**.
3. Через минуту политика откроется по адресу `https://dmitryhmarsky.github.io/work-calendar/privacy.html`. Это же и веб-версия приложения.

## Шаг 1. Аккаунт разработчика Google Play

1. Откройте [play.google.com/console](https://play.google.com/console) и зарегистрируйтесь. Нужен разовый регистрационный взнос (на момент написания $25, точную сумму покажет форма), документ для подтверждения личности и телефон.
2. Выберите тип аккаунта. **Личный** проще. Для **организации** нужен номер D-U-N-S.
3. Правило для личных аккаунтов, созданных после 13 ноября 2023 года: перед выходом в продакшен нужно провести закрытое тестирование, где **минимум 12 тестировщиков не меньше 14 дней подряд** остаются подключёнными ([правило Google](https://support.google.com/googleplay/android-developer/answer/14151465)). Поэтому публикация займёт минимум две недели плюс проверка. Начните искать тестировщиков заранее: друзья, знакомые, чаты. Им нужен аккаунт Google.

## Шаг 2. Ключ загрузки и секреты GitHub

Файл `android/app/debug.keystore` из репозитория для Play не годится: он лежит в открытом доступе. Нужен свой ключ. Выполните на своём компьютере (нужна Java):

```bash
keytool -genkeypair -v -keystore upload.keystore -alias upload -keyalg RSA -keysize 2048 -validity 10000
```

Запомните пароль. Сохраните `upload.keystore` и пароли в надёжное место (менеджер паролей, облако). В репозиторий этот файл **не кладите**.

Переведите ключ в текст:

```bash
# Linux
base64 -w0 upload.keystore
# macOS
base64 -i upload.keystore | tr -d '\n'
```

```powershell
# Windows PowerShell (скопирует результат в буфер)
[Convert]::ToBase64String([IO.File]::ReadAllBytes("upload.keystore")) | Set-Clipboard
```

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**. Создайте четыре секрета:

| Имя | Значение |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | длинная строка из команды выше |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища |
| `ANDROID_KEY_ALIAS` | `upload` |
| `ANDROID_KEY_PASSWORD` | пароль ключа (тот же, если вводили один) |

Google Play подписывает приложение собственным ключом (Play App Signing), ваш ключ нужен только для загрузки. Если потеряете его, доступ можно восстановить через поддержку, но это долго.

## Шаг 3. Собрать AAB

**Actions → Release AAB (Google Play) → Run workflow** (track оставьте `none`). Через 2–3 минуты в запуске появится артефакт **work-calendar-aab**, скачайте его и распакуйте. Внутри `work-calendar.aab`.

Номер версии (`versionCode`) берётся из номера запуска и растёт сам, ничего менять не нужно.

## Шаг 4. Создать приложение в Play Console

**Create app**, затем:

- Название: `WorkTime`. Язык по умолчанию: русский. Тип: **App**.
- **Free или Paid.** Внимание: бесплатное приложение потом нельзя сделать платным, а платное можно сделать бесплатным. Монетизировать бесплатное приложение можно через встроенные покупки, подписки и рекламу. Для этого проекта подходит **Free**.
- Принять декларации.

Затем раздел **Dashboard → Set up your app**, заполните по пунктам:

| Пункт | Что указать для текущей версии |
|---|---|
| Privacy policy | `https://dmitryhmarsky.github.io/work-calendar/privacy.html` |
| App access | Все функции доступны без входа |
| Ads | No, приложение не содержит рекламы (если добавите рекламу, поменяйте на Yes) |
| Content rating | Заполните анкету честно, категория **Утилита / Productivity**, насилия и т. п. нет, результат будет самым мягким |
| Target audience | 18+ (не выбирайте детские возрастные группы, иначе включатся строгие правила Families) |
| Data safety | Данные **не собираются** и **не передаются** (всё хранится на устройстве). Если добавите рекламу или покупки, форму придётся заполнить заново |
| Government / Financial / Health apps | Нет. Расчёт заработка, это не финансовая услуга |
| Contact details | Нужен публичный email и (по желанию) сайт, их увидят в карточке |

**Store listing**: возьмите тексты из `store-assets/listing.md`, значок `app-icon-512.png`, графику `feature-graphic-ru.png` и скриншоты из `screenshots-ru/` (минимум 2). Добавьте переводы: **Translations → Manage translations**, английский, итальянский, украинский. Для английского есть `screenshots-en/` и `feature-graphic-en.png`.

## Шаг 5. Внутреннее тестирование

**Testing → Internal testing → Create new release**, загрузите `work-calendar.aab`, добавьте себя в список тестировщиков (email аккаунта Google), сохраните и опубликуйте. Откройте ссылку-приглашение на телефоне и установите приложение. Проверьте, что оно работает.

## Шаг 6. Закрытое тестирование (для личного аккаунта)

1. **Testing → Closed testing → Create track → Create new release**, загрузите тот же `.aab` (или новый).
2. Создайте список из **12 и больше** email-адресов, отправьте им ссылку-приглашение.
3. Каждый должен принять приглашение и **не выходить из теста 14 дней подряд**. Если кто-то вышел и вернулся, отсчёт у него начинается заново.
4. Через 14 дней на **Dashboard** появится кнопка **Apply for production**. Опишите, как искали тестировщиков, что они говорили и что вы улучшили.
5. Google обычно отвечает в течение 7 дней, иногда дольше.

Если у вас аккаунт организации, этот шаг не нужен.

## Шаг 7. Продакшен

**Production → Create new release**, загрузите `.aab`, укажите «что нового», нажмите **Send for review**. Первая проверка занимает от нескольких часов до нескольких дней.

Следующие версии: меняете код в `www/`, запускаете workflow **Release AAB**, загружаете файл в Play (или включаете автозагрузку ниже).

## Шаг 8 (по желанию). Автозагрузка из GitHub

Чтобы workflow сам отправлял сборку в Play:

1. Google Cloud Console: создайте проект, включите **Google Play Android Developer API**, создайте **Service account** и скачайте ключ в формате JSON.
2. Play Console → **Users and permissions → Invite new users**, пригласите email этого service account и дайте право выпускать релизы для приложения.
3. В GitHub добавьте секрет `PLAY_SERVICE_ACCOUNT_JSON` с содержимым файла.
4. Запускайте **Release AAB** с `track = internal` (или другой). Пока приложение не опубликовано ни на одном треке, оставляйте `status = draft`.

Самую первую загрузку лучше сделать вручную через Play Console (шаг 5).

# Монетизация

Сейчас в приложении нет ни рекламы, ни покупок, и карточка с политикой конфиденциальности написаны под это. Монетизацию стоит добавлять **после** того, как приложение появится в Play: продукты и тестовые покупки привязаны к опубликованному пакету.

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| **Pro за разовую покупку** | Просто понять, нет регулярных обязательств | Доход разовый |
| **Подписка** (месяц или год) | Регулярный доход, лучше всего подходит для облачной синхронизации | Пользователи не любят подписки на простые утилиты |
| **Реклама** (AdMob) | Приложение остаётся бесплатным целиком | Для утилиты доход маленький, нужно согласие на персонализацию в ЕС (форма UMP), больше деклараций в Play, хуже впечатление от приложения |
| **Платное приложение** | Самое простое | Резко меньше установок, и позже его нельзя будет сделать «бесплатным с покупками» (бесплатное нельзя сделать платным, но платное можно сделать бесплатным) |

**Моя рекомендация:** бесплатное приложение с покупкой **Pro**, без рекламы. Сейчас в приложении нет функций, которые можно было бы закрыть за Pro, их нужно добавить. Идеи, которые люди ценят в таких приложениях: несколько мест работы или проектов с разной ставкой, экспорт в CSV и PDF, резервная копия и перенос на другой телефон, виджет на главный экран, сверхурочные с повышенной ставкой, напоминания.

## Комиссия Google

По [официальной странице](https://support.google.com/googleplay/android-developer/answer/112622) на момент проверки: за автопродлеваемые подписки 10% + 5% за биллинг в США, Великобритании, ЕЭЗ, Австралии и Японии, в остальных странах 15%. За разовые покупки в этих регионах 20–25% + 5%, в остальных 15% с первого $1 млн годового дохода. Ставки меняются, перед запуском сверьтесь со страницей.

Чтобы получать деньги, в Play Console заполняется платёжный профиль и налоговая информация. Налоги в Италии (регистрация деятельности, НДС) зависят от вашей ситуации, лучше обсудить с бухгалтером. Я не налоговый консультант.

## Как подключить покупки (Google Play Billing)

Правило Google: цифровые функции внутри приложения продаются через Google Play Billing, свои способы оплаты внутри приложения для этого использовать нельзя (в отдельных регионах есть исключения, проверьте актуальные правила).

1. Опубликуйте приложение хотя бы на внутреннем треке (шаг 5).
2. Play Console → **Monetize with Play → Products → In-app products → Create product**. ID, например, `pro_unlock`. ID потом не меняется. Укажите название, описание и цену, активируйте продукт. Для подписки: **Subscriptions**.
3. **Settings → License testing**: добавьте свои аккаунты Gmail, чтобы тестовые покупки были бесплатными.
4. В коде подключается плагин Billing для Capacitor и проверка покупки. Нужны: запрос продукта, покупка, восстановление покупок («Restore»), проверка при запуске. Плагины: `cordova-plugin-purchase` или RevenueCat (`@revenuecat/purchases-capacitor`). RevenueCat проще (серверная проверка чеков, статистика), бесплатен до порога дохода, но это сторонний сервис, о нём придётся написать в политике конфиденциальности и в Data safety.
5. Обновите политику конфиденциальности (`www/privacy.html`), форму Data safety и декларацию Ads.
6. Выпустите новую версию через шаги 5–7.

## Как подключить рекламу (AdMob)

1. Создайте аккаунт на [admob.google.com](https://admob.google.com), добавьте приложение, получите **App ID** и **Ad unit ID**.
2. В проект добавляется плагин `@capacitor-community/admob`, App ID прописывается в `AndroidManifest.xml`.
3. Для пользователей из ЕС и Великобритании обязательна форма согласия (Google UMP). Без неё показ рекламы нарушает правила.
4. В Play Console: Ads = **Yes**, Data safety: идентификатор рекламы (Advertising ID) и данные об использовании, обновите политику конфиденциальности.
5. Для разработки используйте только тестовые ID от Google, иначе аккаунт AdMob могут заблокировать за самостоятельные клики.

## Что нужно от вас, чтобы я это подключил

Скажите, какую модель выбираете (Pro разово, подписка или реклама) и что должно входить в Pro. Затем создайте продукт или AdMob-приложение и пришлите мне `ID продукта` (или `App ID` и `Ad unit ID`, это не секретные данные). Я добавлю код в приложение, обновлю политику и тексты карточки.
